# Panel spacing refinement

The user's supplied reference establishes one thin outer frame, compact corners, a distinct header band, and aligned body controls. The supplied current crop showed an oversized rounded countdown nested within another rounded panel.

## Applied

- Market and ticket use 12px outer corners and 20px insets, with a subtle divided header band.
- Countdown has no padded background; mobile places its label and fixed-width time on one row.
- Ticket headings remain outside the desktop scrolling body. Draft, held, cashed-out, and closing-bell states share the frame.
- Direction, target and budget choices use 1px borders and 8px corners. Selected direction/budget use restrained color tints.
- Cost/actions sit behind a divider. Held-ticket identity and result breakdowns use dividers instead of nested cards. Scenario disclosure retains one inset surface.
- Existing animation behavior and all game calculations remain unchanged.

## Verification

Inspected mobile market/draft at 390×844 and desktop at 1440×900. Reduced desktop body gap to 16px after inspection showed 7px of unnecessary overflow; confirmed body clientHeight and scrollHeight both 452px. At 320×740, purchased a fictional ticket and advanced to the closing bell through the UI. Held and result states had document scrollWidth/clientWidth both 305px with the browser gutter. Confirmed the settled result rendering after a transient screenshot capture artifact.

TypeScript build, targeted ESLint, CSS architecture check and production Vite build passed. Impeccable detector returned no findings. Vite retains the existing comparison-chunk size warning. No new automated tests for this presentation-only refinement.
