# Decisions

One line per decision made while replacing the screens: what, and why. Newest at the bottom.

The original screen-rewrite entries below are historical. The donor-port decisions at the end supersede conflicting entries about comparison, completed-session retention and workload staleness.

- **Feed: `modules/connection` stays, `feed/wsFeed.ts` goes.** The connection already answers every command with an explicit outcome, marks unanswered commands "checking" when the line drops, resends by id after a reconnect and knows when its data is stale; the older feed did none of that and the order ticket was built against the connection's shape. The board-size hello (the `?board=` stress switch) moved into the connection's feed.
- **Resend after a reconnect: automatic while the press is under 20 seconds old and still the same day (`resendWhileFresh`).** A kid should not have to press twice because the wifi blinked; a resend reuses the command id, so it can never buy twice. Older presses wait for "Retry safely".
- **The store keeps the whole latest frame (`frame` slice) and a per-company chart series.** Every message is the whole picture, so the screens read one picture; the narrow slices stay for the table, which must not redraw per frame.
- **Lesson sentence and rank live in the web app (`screens/words.ts`, `screens/ticket/lesson.ts`).** They choose copy from signs and outcomes the server sent; no money is worked out. Keeping them out of the wire contract kept the server untouched for a copy decision.
- **The frame carries what each company makes (`product`).** The news cards say "RoboPup makes robot pets"; the client has no cast file (the engine is fenced out of the browser), so the frame tells it. Optional on the wire, so old fixtures still parse.
- **Company marks are generated tiles: solid tint plus a glyph, six tints picked to stay clear of mint, coral and sun.** No art this run; the marks from the old desk module were carried over, the palette was not (it reused the profit and cash colours for two companies).
- **The module lab and the module fakes for the deleted screens are gone; the fakes for the connection, the live grid and the order ticket stay** because their kept tests drive them. The two JSON sheets the server tests read moved from the lab to `apps/server/test/fixtures/`.
- **`reference/` is git-ignored** so the prototypes this port was made from never reach the public repository.
- **Fonts are bundled** (`@fontsource-variable/lexend`, `@fontsource-variable/unbounded`), as in v1, so the game works on a school network that blocks font CDNs.
- **Total worth is the big number in the top bar, cash below it only when the amounts differ, and no running "minus" against the starting million.** Buying a ticket turns cash into a ticket worth the same; the old red minus read as a loss before anything happened. Hide the redundant cash amount when all worth is cash.
- **"Play again" closes and reopens the connection** rather than reloading the page: the final frame already made the feed forget its session, so the next hello starts a fresh game.
- **"Compare options" replaces the chart inside the middle column** (a toggle beside the timer), not a drawer: the news column and the ticket stay where they are, so a row picked in the table lands on the same ticket the player was building, and there is nothing to dismiss.
- **Picking a row in the table selects that company and sets the exact contract**; a simple pick (UP or DOWN plus Close, Far or Moonshot) follows the player from company to company by snapping to each board's own targets. The builder shows a table pick as a fourth row, "From the table".
- **The table highlights the selected company's six simple choices**, so the builder and the table point at the same rows.
- **The developer controls hide behind `?dev` on the address** ("Drop the line" in the top bar). Nothing a player sees; the demo opens the page with `?dev` to show the reconnect.
- **While the line is not live, the news and the chart dim and the tip box says why; the ticket panel stays bright** because it carries its own words for the blocked button and the "Checking…" state. Buying and cashing out are off until a fresh frame arrives (the connection's rule, not a timer).
- **The reconnect proof runs against the real service over a real socket** (`apps/web/test/reconnect.e2e.test.ts`), in two shapes: the reply lost after the server took the buy, and the buy never sent. Both end with one ticket and the right cash, and a deliberate repeat of the same id is answered with the first receipt.
- **The "filter while streaming keeps the ticket" proof renders the real page in jsdom** with a stubbed socket (`apps/web/test/desk.filter.component.test.ts`).
- **The what-if slider lives inside the ticket's summary box**, under "You get N tickets for $C", and starts on the break-even stop. Its stops and profits are the server's quote (`draft.ticket.whatIf`); the page only looks a stop up. It replaced the "They pay out if X closes above $T" sentence, which the slider says better.
- **The stress readout is the kept one** (`board/StressReadout.tsx`), shown above the table whenever the frames say `stress`, so `?board=2500` exercises exactly the code path the game uses. Buying is off in a stress game, and the tip under the chart says so.
- **After an adversarial review, six behaviours changed:** a table pick belongs to one company (tapping another company keeps the side and the choice, drops the exact row); picks are frozen while a buy or a cash-out is unanswered, so "Retry safely" always resends the order on screen; the clock buttons ignore the second click of a double-click and press only on a live line; the draft is said again on the first frame after a reconnect, because the server keeps drafts per socket; the requested board size accompanies resumes so expired sessions recreate the workload; if the size is refused, retry without it while retaining the saved session; the table's filter and highlight are rebuilt once a day, not once a frame.
- **Before the opening bell the news cards show the price and "opens here", no change against yesterday:** the lead-in the server sends is yesterday's tail, not yesterday's open, so a percentage against it would contradict yesterday's debrief.
- **Known and left alone:** in a stress game (`?board=`) at 3× and 7.5× pace the chart waits for whole frames because quote batches skip price indexes; and before the bell in a stress game whole frames arrive every 1.5 s, right at the stale threshold, so the status can blink. Buying is off in stress games, so neither touches money.
- **Rebase cleanup: restore the obsolete-file removals and fixture moves from the port's root snapshot (`7b8215e`).** Rebasing only its descendants onto `main` left the old desk, lab, feed, and their UI tests behind. Remove those files and move the two server fixtures out of the lab. Keep the newer cash-out, settlement, and news regression tests from `main`, along with the newer order-ticket contract and handler changes; they are not obsolete screen code.

## Donor port, 22 September 2026

- Keep Fable's screen, store and module boundaries. Port capabilities, not the donor's monolithic application or palette. No economic-rule or engine-model changes.
- Comparison collapses the news rail, keeps a compact annotated chart, and retains the ticket beside the grid. Company chips drive the chart/builder selection; the redundant dropdown is removed. Side and affordability filters remain independent. All shows every company while keeping the current chart. The grid stays mounted after first opening so same-day filters, sorting and selection survive toggles.
- All companies use full-width cards, including a no-news variant. The company list scrolls with a hidden scrollbar and edge fades only where more content remains; wheel, touch and keyboard scrolling remain available.
- Live numeric text must not size surrounding UI. The bundled Lexend font lacks tabular figures, so body/grid numbers use the system monospace stack; Unbounded display amounts retain its actual tabular figures. Totals, clocks, quote columns, chart price bubbles, profit badges and trade-action amounts reserve space across digit-count changes. The cash row keeps its height when its redundant text is hidden. Quote summaries use stable rows rather than changing-length prose, and large ticket values size to the panel rather than the current amount.
- A versioned journal stores only the exact money-changing intent, session/day and wall-clock submission time. `connection.restore` registers it without sending. Receipts precede retry eligibility; restored age is translated onto the monotonic clock. The existing 20-second automatic retry policy remains. Old eligible intents require explicit same-ID retry; unrelated/closed intents are unverified, never fabricated accepted/rejected outcomes.
- Final frames retain their session. Play again closes the old connection, clears that board's session/journal keys and reloads, which also resets the feed's in-memory ID and UI. Normal and workload sessions keep separate keys.
- `deriveSlice` gives routing, clock, account, news, days and screen-specific snapshots stable identities. Clock-only changes do not invalidate ticket/news/board configuration. No JSON-stringification equality or additional state library. Connection status consumers ignore receipt timestamps that do not change visible status.
- Load comparison/AG Grid through a retryable lazy boundary. Check Vite's manifest to keep its static dependency graph out of the initial route; report initial and deferred JavaScript separately.
- Preserve chart shading, target/break-even and entry/exit markers; inspection uses only received observations. Compact labels have separate reserved positions. The owned ticket always comes from authoritative positions, even while another company's chart is selected.
- Custom whole-dollar edits feed nullable spend through the existing machine and draft pacer. Invalid edits remove the actionable old quote; values are not clamped. Help uses a native modal dialog with Escape and focus restoration.
- Reveal `wasTrue` only after the corresponding day completes, in the public projection shared by samples and replies. Review target, premium and timing independently of news truth. Earlier final-day selections use position/day records, never day-five news/history.
- The optional workload link uses `/?board=2500&dev` in a separate tab. Hide budget-dependent grid costs; label complete quote scenarios and their cadence. Only this read-only mode uses a 3-second connection silence threshold to accommodate 1.5-second complete frames. Normal trading retains 1.5-second stale-action blocking. Accelerated chart gaps still await received complete history rather than fabricated points.
- Preserve Render's single-service build/start/health contract and toolchain pins. Fix Windows verification launchers with `file:` loader URLs and drain real sockets between controlled workload ticks. The multi-process content CLI test has a Windows-specific time budget; the news CLI checks were split by invocation without weakening assertions. Browser screenshots and performance observations require an available browser and are not inferred from jsdom tests.
